# Asset policy (rule #1)

**Nothing from the game is ever stored in this repository.** Everything is
built on the user's machine from files the user supplies. The same applies
to other titles used for testing, and to any other proprietary material.

## Not allowed

In any form (files, string literals, fixtures, snapshots, docs):

* assets: models, textures, shaders, audio, video, text, archives;
* the executable or any part of it: data sections, strings, tables,
  resources, code beyond the signatures below;
* anything derived from those: converted assets, decompiled or
  disassembled code, shader dumps, extracted tables, screenshots.

## Allowed

* our own code that understands formats;
* build identities: BLAKE3 of an executable, CodeView GUID/age;
* per-build offsets of functions we hook, under names we choose;
* byte-pattern signatures that locate functions or data in the executable;
* small interoperability constants (magic numbers, enum values) we write;
* synthetic test data generated by our own code.

## The one exception

`crates/victory-formats/src/bcpack-tables.bin` (about 78 KB): the constant
tables of the BCPack format (entropy models, index rank tables, control
codes, per-format dictionaries). A BCPack stream cannot be decoded without
exactly these tables and they cannot be derived, so they ship with VIctory
by the project owner's decision (2026-11-23), entered as an exception in
`xtask/src/policy.rs`. They are part of the format, not our work, and the
repository's licence does not cover them. Nothing else of this kind is
accepted.

The entry pins the file's length and hash, so anything else at that path
fails the check.

`crates/victory-gpu/src/clamp_bytecode.rs` has an entry too, for a
different reason. It is our own shader, `clamp.hlsl`, compiled by
Microsoft's compilers and written as an array of bytes, which is the shape
the check refuses. It holds nothing from a game.

## Where data lives

Outside the repository, configured in `victory.toml`: `game_dir` (the
user's dump), `test_titles`, and `cache_dir` for everything derived
(default `%LOCALAPPDATA%\victory\cache`).

## Enforcement

1. `.gitignore` keeps common data types out of `git status`.
2. `cargo xtask policy` (run by the pre-commit hook; install with
   `cargo xtask install-hooks`) is an allowlist: files must have an allowed
   type, be under 512 KiB, contain no binary data or known binary
   signatures, and hold no long hex/base64 runs or long lists of numeric
   literals (see below). Pictures of our own in
   `docs/images` are the only binary type. Exceptions need an entry in
   `xtask/src/policy.rs` with a reason and the file's length and hash.
3. At runtime, everything that writes derived data calls
   `victory_core::ensure_outside_repo`.
4. Tests that need real files take their paths from environment variables
   and skip when unset. They assert on properties, never on snapshots.

### What counts as a list of numeric literals

A file may hold no list of more than 1024 numeric literals. The check
reads every text file the same way, whatever its type:

* A literal is an optional `-`, a digit, and the letters, digits and
  underscores that follow: `77`, `-3`, `0x4d`, `0xFFFF_0000u32`, `1e5`.
  It counts when a comma or a closing `]`, `)` or `}` follows it.
* The list goes on across commas, brackets of all three kinds, spaces and
  line breaks. Rows (`[1, 2], [3, 4]`) and tuples (`(1, 2), (3, 4)`) are
  one list of four.
* Comments do not split a list: `//` and `#` to the end of the line, and
  `/* ... */`. A list written inside comments is counted too.
* Anything else ends the list: a name, a string, an operator, a
  semicolon. The limit is on one list, not on a file's total.

Not counted, so not caught by this rule:

* numbers with a decimal point (`1.5`): only the digits after the point
  can count, so a list of them is a list of one;
* numbers inside strings, or with a name or string between every two of
  them (`(1, "a"), (2, "b")`);
* lists split by a comment form of another language (`rem`, `<# ... #>`).

The size limit and the hex/base64 rule still apply to all of these, and
review is what stands behind the check.

## If something slips through

A follow-up commit is not enough. Rewrite history
(`git filter-repo --path <file> --invert-paths`), force-push, and have
everyone re-clone.
